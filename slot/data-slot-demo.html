🗺️ data-slot — 4 rules là đủ

309 slots trông đáng sợ, nhưng tất cả đều sinh ra từ 4 grammar rules cực kỳ đơn giản.

<!-- Ai biết đây là cái gì? --> <div class="flex flex-col gap-2 p-6 rounded-lg border bg-card text-card-foreground shadow-sm"> <!-- 12 class, 0 meaning --> </div>

12 Tailwind classes, nhưng agent không biết đây là Card hay Dialog hay Sheet.

 <!-- Ngay lập tức biết --> <div data-slot="card"> <div data-slot="card-header"> <div data-slot="card-title">Login</div> </div> </div>

1 attribute, 100% semantic. Agent parse: split("-")[0] → parent.

4 Grammar Rules

Pattern: Component name = slot name
data-slot="button" · data-slot="card" · data-slot="dialog"

Pattern: {parent}-{child}
card-header · card-title · dialog-content

Pattern: Flat names, never deeply nested
sidebar-menu-button = OK
sidebar-menu-sub-button-icon = ❌ Không tồn tại

Pattern: 14 suffix roles reused everywhere
-content · -trigger · -item · -title · -header

✅ Key insight: Bất kỳ slot nào, chạy slot.split("-")[0] → parent component. Chạy slot.endsWith("-trigger") → biết ngay đây là nút mở. Zero inference needed.

🏗️ Production Patterns & Edge Cases

3 patterns thực tế + 3 edge cases bạn cần biết.

Khi nào: Agent tạo Figma node từ component spec

// data-slot → Figma node name const role = spec.role; // "card-header" const frame = figma.createFrame(); frame.name = role; // Figma name = data-slot value ⚠️ Gotcha: Figma node names are display labels, not IDs. Duplicate names are valid in Figma.

Khi nào: Override style cho specific slot

/* Target bất kỳ card-title nào */ [data-slot="card-title"] { font-weight: 700; letter-spacing: -0.02em; } /* Target header bên trong dialog */ [data-slot="dialog-content"] [data-slot="dialog-header"] { border-bottom: 1px solid var(--border); }

Khi nào: Tìm tất cả components dùng 1 suffix pattern

// Tìm mọi component có -trigger slot const withTrigger = Object.entries(vocab.byComponent) .filter(([k, slots]) => slots.some(s => s.endsWith('-trigger'))) .map(([k]) => k); // → ["accordion","collapsible","combobox","context-menu",...] // → 16 components have triggers

⚡ Edge Cases

💡 Expected: Rule 3 says max depth 2 → this should not exist
❌ Actual: sidebar-menu-sub-button IS a valid slot
🔍 Why: The "depth" rule counts name segments, not nesting. sidebar-menu is the parent group, sub-button is the child role. The grammar is flat naming, not tree nesting.
✅ Fix: Parse by known component prefix first (sidebar), then match role.

💡 Expected: Each slot belongs to exactly 1 component
❌ Actual: calendar slot appears in both calendar AND calendar-hijri
🔍 Why: calendar-hijri is a locale variant that reuses the same slot name
✅ Fix: Use byComponent map (not slots array) to resolve ambiguity

💡 Expected: checkbox-group thuộc component checkbox
❌ Actual: Nó thuộc field-group, form-rhf-checkbox, form-rhf-complex, form-tanstack-checkbox, form-tanstack-complex — KHÔNG thuộc checkbox!
🔍 Why: checkbox-group là form-level composition, checkbox component chỉ có checkbox + checkbox-indicator
✅ Fix: Luôn tra byComponent thay vì đoán từ tên slot

Key concepts:

• data-slot = semantic identity cho mỗi HTML element trong component
• 4 grammar rules → sinh ra toàn bộ 309 slots từ 60 components
• 14 suffix patterns (-content, -trigger, -item...) reused across ecosystem
• Agent parsing: split("-")[0] → parent, endsWith("-X") → role
• Bridge mapping: data-slot value = Figma node name = Spec JSON role

⚠️ Limitations — điều data-slot CHƯA giải quyết

data-slot chỉ để đọc. Không có mutation API — bạn không thể setSlot(). Muốn thay đổi phải sửa source code.

data-slot cho biết "dialog-content" nhưng không cho biết dialog đang open hay closed. State nằm ở data-state (khác attribute).

shadcn v5 có thể thêm/sửa/xóa slots. Vocabulary 309 slots hôm nay sẽ thay đổi. Cần re-extract định kỳ.

data-slot không cho biết Dialog có thể chứa Button. Composition knowledge nằm ngoài protocol — agent phải reason thêm.
