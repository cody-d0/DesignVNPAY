# Phase 3: PRD Structure Gen

**Tham chiếu:** `conventions.md` (Output Structure + Image Path Convention + AI Badge).

## Mục tiêu

Sinh overview file + feature files theo đúng cấu trúc 5 section XPOS PRD.

### Điều kiện vào Phase 3 (khi enable_ocr_reconciliation === true)

Chỉ được chạy Phase 3 nếu đã có file `{output_dir}/.handoff/.ocr_done` (được ghi ở Phase 2g sau khi OCR thành công cho mọi screen có ảnh). Nếu `enable_ocr_reconciliation === true` mà file không tồn tại: không sinh draft, báo mã `OCR_GATE_FAILED` và tham chiếu Phase 2 § Implementation 2g (checklist + gate artifact). Khi `enable_ocr_reconciliation === false`: bỏ qua kiểm tra này.

## 3a. Sinh Overview file

File: `{product-slug}-overview.md`

### 3a-pre. Build `feature_file_plan` (bắt buộc trước Overview + feature files)

Sinh danh sách chuẩn để dùng chung cho cả overview và file features:

- Nguồn: **chỉ** `screen_boundaries`. Mỗi item tối thiểu gồm: `section_slug`, `screen_id`, `screen_name_vi`, `file_slug`, `file_path`, `source_node_ids[]`.
- Nếu không có boundaries trong section thì áp dụng **Determinism rule** (phase-2 § 2a-bis): fail hoặc fallback theo `allow_section_fallback`.
- Overview mục 3 + mục 8 và bước 3b phải dùng cùng `feature_file_plan` này (không build lại từ nguồn khác). `feature_file_plan` được build **chỉ** từ `screen_boundaries`; số file .md = số **biên màn hình**, không phải số artboard hay số ảnh.

**Cấu trúc (XPOS overview):** Heading `# {Product} — Tổng quan sản phẩm`; câu giới thiệu; `---`; Mục lục 1-8; Section 1 Chân dung khách hàng (bullets Đối tượng, Quy mô, Lĩnh vực, Nhu cầu); Section 2 Tổng quan (**{Product}** là ... + Đơn vị tham khảo, Giá trị cốt lõi); Section 3 Tính năng chính (bảng STT | Tên | Mô tả, `|:---:|---|---|`); Section 4 Phạm vi (4.1 In Scope, 4.2 Out of Scope); Section 5 Hệ thống tích hợp; Section 6 Success Metrics; Section 7 User Flow chính (numbered list); Section 8 Cấu trúc tài liệu PRD (bảng STT | Tài liệu | Mô tả, link `./{page}/{section}/{screen-slug}.md`); footer `*Generated by VNPAY Agentic Framework*`.

**Style:** Đọc `XPOS/XPOS PRD/xpos-app-overview.md` để lấy format chính xác. Bắt buộc: `---` separator giữa MỌI section; bảng căn STT trung tâm `|:---:|---|---|`; footer `*Generated by VNPAY Agentic Framework*`.

**Section mapping (đúng thứ tự):**

| # | Overview Section | Nguồn | Cách sinh |
|---|------------------|-------|-----------|
| 1 | Chân dung khách hàng | `product_description` hoặc Phase 4d | Nếu user cung cấp: dùng trực tiếp, format `- **Đối tượng:** ...`. Nếu không: để trống, Phase 4d sẽ bổ sung bằng `🤖 by AI` badge. |
| 2 | Tổng quan sản phẩm | `product_name` + `product_description` | Format: `**{Product}** là {mô tả}.` + `- **Đơn vị tham khảo:** ...` + `- **Giá trị cốt lõi:** ...` |
| 3 | Tính năng chính | `feature_file_plan` | Bảng `| STT | Tên tính năng | Mô tả |` với `|:---:|---|---|`. **Mỗi distinct screen = 1 row**. Không build trực tiếp từ `screen_inventory.screens` để tránh lệch số lượng. |
| 4 | Phạm vi sản phẩm | Suy từ screens | `### 4.1. In Scope (MVP)` + bullet list. `### 4.2. Out of Scope & Roadmap` + `- **{Category}:** {description}.` |
| 5 | Hệ thống cần tích hợp | Suy từ components | Format: `- **{System}:** {description}.` + nested bullet cho API doc link. |
| 6 | Success Metrics | UNSPECIFIED | Format: `- **{Metric}:** {description}.` Đánh dấu cần bổ sung. |
| 7 | User Flow chính | `flow_graph` | Numbered list: `1. **{Giai đoạn}:** {flow}.` |
| 8 | Cấu trúc tài liệu PRD | `feature_file_plan` | Intro paragraph + bảng `| STT | Tài liệu | Mô tả chức năng |`. **Mỗi item trong `feature_file_plan` = 1 row**. Link: `[{Tên}](./{page}/{section}/{screen-slug}.md)`. Không gộp nhiều màn vào 1 row. |

**Ràng buộc Overview:** Số dòng mục 3 = số dòng mục 8 = số item `feature_file_plan` = số feature file .md = số Page Object cho UI automation.

## 3b. Sinh Feature files

Sinh file theo `feature_file_plan` (không tự suy lại từ nguồn khác). Số file = số item trong `feature_file_plan` (mỗi screen 1 file .md). Theo **Output Structure** trong `conventions.md`.

File: `{screen-slug}.md` (trong section folder khi section_folder; tại output_dir khi flat).

**Ràng buộc theo biên màn hình:** Mỗi file .md tương ứng **một biên màn hình**; nội dung (Section 1–5, đặc biệt Section 3 Wireframe và các block OCR) chỉ dùng dữ liệu của **đúng** biên đó (`wireframe_images`, `ocr_*`, `components` của screen k). Không gộp dữ liệu nhiều biên vào một file; không tách một biên thành nhiều file.

**Cấu trúc (XPOS feature 5 section):** Heading `# {Feature} — PRD ({Tên tiếng Việt})`; câu giới thiệu; Mục lục 1-5; Section 1 User Flow (câu intro + `### 1.x. {Tên luồng}` + bảng 4 cột Bước | Tên màn hình | Tên hành động | Kết quả); Section 2 User Story (bảng 6 cột, AC dùng `<br>`); Section 3 Wireframe (`### Hình ảnh minh họa` + `![alt](ui/filename)` từ wireframe_images + `### Mô tả màn hình` + bảng); Section 4 Thiết kế Database (intro + `### Entity: ...` + bảng Field | Data Type | Constraint | Description); Section 5 Non-functional requirement (bullets Bảo mật, Hiệu năng, Trải nghiệm, 4-space indent); footer `*Generated by VNPAY Agentic Framework*`.

**Style:** Đọc `XPOS/XPOS PRD/xpos-app/register.md` (feature mẫu) để lấy format chính xác. Bắt buộc: `---` separator giữa MỌI section; User Story `<br>` cho AC; footer `*Generated by VNPAY Agentic Framework*`.

### Section 1: User Flow

**Nguồn:** `flow_graph` edges liên quan đến screen này. **Format mẫu:** `register.md` Section 1 — group by luồng, mỗi luồng `### 1.x.` + bảng 4 cột `|:---:|---|---|---|`.

COMPbase: citation `figma:{fileKey}/{nodeId}`, không badge. UNSPECIFIED: `🤖 by AI` badge, Độ tin cậy: Low.

**Flow variant coverage (bắt buộc):**
- **Happy path:** Ít nhất 1 flow COMPbase cho màn hình (luồng chính từ form → confirm → result hoặc tương đương).
- **Variant paths:** Mỗi artboard variant tương ứng 1 flow riêng khi khác hành vi (vd: "Đặt lịch hàng tháng" vs "Không lặp lại" vs "Chuyển ngay không đặt lịch").
- **Validation/Error flow:** Nếu Figma có modal/error text (vd: "Số lần giao dịch không được vượt quá 10 lần") → bắt buộc có flow riêng (vd: `### 1.4. Validation lỗi "Số lần giao dịch"`) với bảng Bước → Hành động → Kết quả (modal hiển thị, nút Đóng).
- **Back navigation:** Bắt buộc có flow khi màn hình có nút "Quay lại" / "Back" (1 bước: Quay lại → quay màn trước, giữ data).
- **Minimum flow count per screen:** Màn form ≥ 2 flows (happy path + error/validation hoặc back). Màn confirm ≥ 2 (xác nhận + quay lại). Màn result ≥ 2 (tạo mới + chia sẻ/lưu hoặc về trang chủ).

### Section 2: User Story

**Nguồn:** `screen_inventory.components` + `flow_graph` + text_nodes. **Format mẫu:** `register.md` Section 2 — bảng 6 cột trực tiếp sau heading, không có intro paragraph.

**Ràng buộc (không có trong file mẫu):**
- Mã US: `US-{NNN}` auto-increment toàn pack, không reset giữa files
- "Mô tả chi tiết": "Là {persona}, tôi muốn {action} để {benefit}."
- Business Rule: chỉ COMPbase khi có Figma evidence; không có → UNSPECIFIED
- AC: `<br>` phân tách, bao gồm states có evidence
- **Granularity (minimum):** Mỗi input field logic riêng → 1 US; mỗi toggle/switch → 1 US; mỗi validation rule có evidence (threshold/constraint cụ thể, không generic) → 1 US; mỗi navigation action → 1 US
- AC bao gồm sample data từ Figma text nodes khi có (vd: "Số dư 20,000,000 VND", "39/50 ký tự")

### Section 3: Wireframe

**Nguồn:** `screen_inventory.wireframe_images` (đã điền alt_text ở Phase 2f) + screen_inventory.components + `ocr_full_table`, `ocr_screen_context`, `ocr_ux_improvements`, `ocr_gaps` (Phase 2g). Cấu trúc Section 3 theo **thứ tự cố định 7 block** dưới đây; chỉ xuất mỗi block khi có dữ liệu tương ứng (scale theo nhóm A/B/C).

**Thứ tự 7 block (luôn giữ thứ tự khi xuất):**

1. **`### Hình ảnh minh họa`** — Luôn xuất. Ảnh theo `wireframe_images[]`; link theo **Image Path Convention** trong `conventions.md`. Alt: dùng đã gán ở Phase 2f (1:1 filename ↔ alt, không sinh lại).
2. **`### Mô tả màn hình`** — Luôn xuất. Một bảng: **STT | Tên màn hình | Loại thành phần | Mô tả** (4 cột chuẩn). Nguồn: `screen_inventory.components` (đã gồm row từ 2b **và** 2b-bis — Nhóm A: component mapped + Design element). Cột "Mô tả" bắt buộc chi tiết (sample data từ Figma text nodes). Mỗi section/button/modal = 1 row riêng. **Cột "Nhóm" (tùy chọn):** Chỉ thêm cột thứ 5 khi `include_unmapped_elements === true` và có ít nhất một row với `prd_type` = "Design element" (hoặc "Illustration"/"Decoration"); giá trị cột: `COMPbase` hoặc `Design element`. Nếu không có Design element thì giữ bảng 4 cột (tương thích ngược). Ưu tiên subsection riêng cho B/C; có thể gộp ocr_gaps vào bảng dưới dạng row "Spec từ ảnh" nếu cần, nhưng subsection riêng dễ scale hơn.
3. **`### Kết quả OCR (toàn bộ)`** — **Xuất khi** đã chạy OCR và có `screen_inventory.screens[k].ocr_full_table`. Bảng bắt buộc: **Ảnh | Loại (text / icon) | Nội dung | Vị trí | Đã khớp spec (Y/N)**. Nguồn: `ocr_full_table`; cột "Vị trí" chỉ điền khi `type === "icon"` (position_zone, position_detail); với row text để trống. Mỗi row citation `ocr:{filename}`. Block này liệt kê toàn bộ item OCR trước; subsection "Spec còn thiếu" (block 6) chỉ xuất các dòng gap từ bảng này.
4. **`### Ngữ cảnh màn hình (từ OCR)`** — **Chỉ xuất khi** `screen_inventory.screens[k].ocr_screen_context` tồn tại và không rỗng. Nội dung: 1 đoạn ngắn từ `ocr_screen_context`; citation `ocr:{filename}` hoặc "ocr:screen". Không badge (COMPbase từ OCR).
5. **`### Thông số design (tham khảo)`** — **Chỉ xuất khi** `include_design_specs === true` và `screen_inventory.screens[k].design_spec_summary` tồn tại (Nhóm B). Sau bảng "Mô tả màn hình". Nội dung: blockquote với badge `🤖 by AI` | Nguồn: figma:{fileKey}/{nodeId} | Độ tin cậy: Medium. Bullet hoặc bảng rút gọn từ `design_spec_summary` (gap, padding, border-radius, auto-layout). Tham khảo cho L4/token, không phải CSS.
6. **`### Spec còn thiếu (phát hiện từ ảnh)`** — **Chỉ xuất các dòng gap:** item từ `ocr_full_table` có `matched_spec = N` (hoặc từ `ocr_gaps.missing_text` / `ocr_gaps.missing_components` đã sinh từ bảng OCR). **(a)** Khi có gap: bảng 2 cột (Loại | Nội dung) hoặc bullet; mỗi dòng citation `ocr:{filename}`. **(b) Fallback:** OCR đã được thử nhưng `ocr_gaps` **null hoặc không tồn tại**: xuất subsection với nội dung placeholder trong blockquote: *"Chưa chạy OCR vision (2g hoặc 2g-bis)."* Citation: `ocr:not-run`.
7. **`### Đề xuất cải thiện UX (từ OCR)`** — **Chỉ xuất khi** `screen_inventory.screens[k].ocr_ux_improvements` tồn tại và không rỗng. Nội dung: bullet hoặc bảng ngắn (Đề xuất | Citation | DDL); mỗi dòng khi có `ddl_ref` phải ghi rõ (vd. `ux-guidelines.csv#22`). Blockquote với badge `🤖 by AI` | **Nguồn:** ocr + components + DDL (ux-guidelines / web-interface) | Độ tin cậy: Medium.

**Quy tắc chung:** Chỉ xuất subsection (block 3, 4, 5, 6, 7) khi có dữ liệu; riêng block 6 có thêm fallback (b) khi OCR đã thử nhưng ocr_gaps null. Block 3 "Kết quả OCR (toàn bộ)" bắt buộc khi đã chạy OCR; bảng có cột Vị trí (cho row icon). Block 6 "Spec còn thiếu" chỉ gồm các dòng gap từ bảng đó. Nhóm D (chuẩn hóa ngôn ngữ / term-equivalents) không có block riêng trong Section 3 — chỉ ảnh hưởng dữ liệu vào bảng (block 2).

### Section 4: Thiết kế Database

**Nguồn:** component text labels (field names) + inferred entities. **Format mẫu:** `register.md` Section 4 — intro paragraph + `### Entity: {Name} ({Mô tả})` + bảng 4 cột backtick field names.

**Ràng buộc:** Toàn bộ entity tables nằm trong `🤖 by AI` badge vì là INFERRED (`figma_inferred:{fileKey}/{nodeId}`). Types suy từ field format (số tiền → Decimal, SĐT → String(10), ngày → DateTime). Thiếu evidence → ghi intro + badge, bỏ bảng.

### Section 5: Non-functional requirement

**Nguồn:** ui-ux-pro-max defaults + Figma evidence. **Format mẫu:** `register.md` Section 5 — bullets `- **Category:**` + 4-space indent items.

**Ràng buộc:** Thứ tự category cố định: **Bảo mật** → **Hiệu năng** → **Trải nghiệm** (→ **Tính ổn định** nếu có async). COMPbase: suy từ Figma evidence (timer → timeout, QR → bảo mật IPN). COMPextend (accessibility, touch target, animation): nằm trong `🤖 by AI` badge.
